## 2. 检查 `.gitignore` 生效

确认以下内容**不会**被提交：

```bash
git status --porcelain | grep -E 'build/|\.gradle/|libs/|backup/|\.jar$'
```

应当只有 `gradle/wrapper/gradle-wrapper.jar` 符合（它必须提交）。
`backup/` 存放的是本地快照、被删除文件的备份和内部脚本，不进入仓库。

## 3. 本地全量构建

```bash
# 需要 JDK 25（JDK 26/27 会让 Lombok 1.18.42 崩溃）
./gradlew buildAndCollect
./gradlew :fabricWrapper:build
```

产物：

- `build/libs/<mod_version>/<mc_version>/litematic-printer-Ling-<mc>.jar`（16 个版本）
- `fabricWrapper/build/libs/litematic-printer-Ling-all.jar`（全版本合一）

Windows 下可直接双击 `build-all-versions.bat`。

## 4. 初始化仓库并推送

这台机器上未安装 Git。三种上传方式（推荐用 GitHub Desktop）见
[上传到GitHub.md](上传到GitHub.md)。

命令行方式：装好 [Git for Windows](https://git-scm.com/download/win) 后，在仓库根目录执行：

```bash
git init
git add .
git commit -m "feat: initial public release of Litematic Printer Ling"
git branch -M main
git remote add origin https://github.com/ling23323/Litematic-Printer-Ling.git
git push -u origin main
```

如果远端仓库在创建时已经生成了 `README` / `LICENSE`，先 `git pull --rebase` 再推，
或者用 `git push -f` 覆盖（远端没有别人的提交时才可以）。

## 6. 可选：发布到 Modrinth

`.github/scripts/publish-modrinth.sh` 里默认的 `MODRINTH_PROJECT_ID` 仍是模板值，
接自己的项目时要改：

1. 在 Modrinth 创建项目，拿到 project id
2. 修改脚本里的 `MODRINTH_PROJECT_ID` 默认值，或通过环境变量传入
3. 仓库 Secrets 添加 `MODRINTH_TOKEN`
4. 确认 `build.yml` / `release.yml` 里发布步骤的 `if` 条件符合预期
